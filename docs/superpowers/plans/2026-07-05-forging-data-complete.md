# 锻造系统：材料掉落与配方大全

> **设计文档** — 定义完整的锻造材料掉落体系 + 全部可锻造装备配方

**版本:** v2.0  
**基于:** `weapons.json` (66武器 + 38防具), `items.json` (14材料), 现有掉落系统

---

## 0、三阶材料体系（设计核心）

```
每个配方 = 基础材料(凡品) × N  +  强化材料(灵品) × N  +  核心材料(帝品) × N
```

- **基础材料**：精铁、百年灵草 — 所有配方必用，保证低阶材料永不贬值
- **强化材料**：赤炎石、紫金沙、魔核碎片、幽魂草、亡者之息、星辉晶砂、灵兽骨、天火熔晶、九幽寒铁
- **核心材料**：玄冰之核、月光粉尘、龙骨髓、妖丹、混沌源石

高阶玩家获取低阶材料的效率，靠高阶 Boss 的「数量倍增」实现。三种新材料的加入使配方多样化，避免单一材料过度集中。

## 二、武器锻造配方（共 33 把武器 × 4 品质 = 全覆盖）

### 2.1 配方设计原则

1. **每把可锻造武器对应一个配方**（不存在于 recipes 中的武器只能通过掉落获取）
2. **配方按等级阶梯排列**：锻造等级 = 用来解锁该配方的最低要求
3. **产出 = weapons.json 中实际存在的武器模板**
4. **材料消耗与武器品阶正相关**
5. **低阶武器 (下品符器~上品法器) 全覆盖；高阶武器 (下品纯阳~无上仙器) 精选代表**
6. **每品 3 把武器中，锻造覆盖 2 把（攻击型 + 暴击型），留 1 把（平衡型）仅限掉落**

#### 特殊合成：原罪 + 无罪 → 天罪

**天罪** 无法直接锻造，必须通过 **合成** 两把残缺神器获得：

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 锻造 **原罪（残缺）** | 使用 forge_053a 配方 |
| 2 | 锻造 **无罪（残缺）** | 使用 forge_053b 配方 |
| 3 | 使用 /融合 <原罪ID> <无罪ID> | 消耗两把武器，产出天罪 |

**合成规则：**
- 消耗原罪和无罪各一把（必须未装备）
- 产出天罪的品质 = **max(原罪品质, 无罪品质)**
- 天罪继承两把武器上的**全部词条**（原罪词条 + 无罪词条，去重后取最高值）
- 天罪的属性 = weapons.json 中"天罪"的固定模板属性
- source_recipe = "forge_053_fusion"

**合成示例：**
```
原罪（上品）[连击+4% 破甲+5%] + 无罪（极品）[精准+3% 铁壁+3% 暴伤+0.1]
  -> 天罪（极品）[连击+4% 破甲+5% 精准+3% 铁壁+3% 暴伤+0.1]
```

## 七、掉落装备实例化

### 7.1 设计规则

所有「仅限掉落（不可锻造）」的装备（共 29 把武器 + 18 件防具），在从 Boss/秘境/悬赏等途径产出时，不再作为静态物品存入储物戒，而是**直接生成带品质和词条的武器实例**。

| 属性 | 值 |
|------|-----|
| 默认品质 | **上品**（×1.2） |
| 默认词条数 | **3 条**（从词条池随机选取，不重复） |
| 存放位置 | `weapon_instances` 表（与锻造武器同一张表）|
| 是否可装备 | 可以，与锻造武器共用装备流程 |
| 是否可分解 | 可以，按上品回收率（40%）|
| source_recipe | 空字符串（标注为掉落来源，不可通过配方逆推）|

### 7.2 掉落实例化流程

```
Boss 击杀 → 确定掉落「精元符剑」（不可锻造）
  ↓
调用 create_drop_weapon_instance(player, template_name)
  ↓
1. 从 weapons.json 读取模板属性
2. 品质固定为 上品 (quality_mult = 1.2)
3. 随机选取 3 条不重复词条
4. 计算实例属性 = 模板属性 × 1.2
5. INSERT INTO weapon_instances (source_recipe = '')
6. 提示玩家：获得「精元符剑·上品 [嗜血+3% 破甲+5% 暴伤+0.1]」
```

### 7.3 需要新增的方法

在 `core/forging_manager.py` 中新增：

```python
async def create_drop_weapon(
    self, player: Player, template_name: str, item_type: str
) -> str:
    """Boss/秘境掉落武器实例（默认上品+3词条）"""
    # 1. 读取模板
    template = self.config_manager.weapons_data.get(template_name)
    if not template:
        return ""

    # 2. 固定品质 = 上品
    quality = "上品"
    qmult = QUALITY_MULT["上品"]  # 1.2

    # 3. 随机 3 条不重复词条
    affixes = random.sample(FORGE_AFFIXES, k=min(3, len(FORGE_AFFIXES)))
    affix_list = [{"name": a["name"], "attr": a["attr"], "val": a["val"]} for a in affixes]

    # 4. 计算属性
    instance_id = self._generate_instance_id()
    data = {
        "instance_id": instance_id,
        "template_name": template_name,
        "item_type": item_type,
        "source_recipe": "",  # 掉落来源，无可逆推配方
        "quality": quality,
        "quality_mult": qmult,
        "enhance_level": 0,
        "atk_bonus": template.get("atk_bonus", 0.0) * qmult,
        "crit_rate": int(template.get("crit_rate", 0) * qmult),
        "crit_damage": template.get("crit_damage", 0.0) * qmult,
        "armor_pen": int(template.get("armor_pen", 0) * qmult),
        "lifesteal": int(template.get("lifesteal", 0) * qmult),
        "double_hit": int(template.get("double_hit", 0) * qmult),
        "damage_reduction": template.get("damage_reduction", 0.0) * qmult,
        "mp_bonus": template.get("mp_bonus", 0.0) * qmult,
        "def_buff": template.get("def_buff", 0.0) * qmult,
        "dodge_rate": int(template.get("dodge_rate", 0) * qmult),
        "crit_resist": int(template.get("crit_resist", 0) * qmult),
        "reflect_pct": int(template.get("reflect_pct", 0) * qmult),
        "block_value": int(template.get("block_value", 0) * qmult),
        "hp_regen_pct": template.get("hp_regen_pct", 0.0) * qmult,
        "affixes": affix_list,
    }
    await self.db_extended.create_weapon_instance(player.user_id, data)
    return instance_id
```

### 7.4 对接掉落系统

需要在以下掉落点调用 `create_drop_weapon`：

| 掉落源 | 文件 | 需要修改位置 |
|--------|------|------------|
| Boss 掉落 | `managers/boss_manager.py` | `_roll_boss_drops()` — 当掉落物品是武器/防具时，调用实例化而非存储物戒 |
| 秘境奖励 | `managers/dungeon_manager.py` | 结算流程 — 当奖励为武器/防具时 |
| 悬赏奖励 | `managers/bounty_manager.py` | 奖励发放 — 当发放物品为武器/防具时 |

**判断逻辑：** 如果掉落物品名在 `weapons.json` 中存在，说明是武器/防具 → 调用 `create_drop_weapon` → 存入 `weapon_instances`。否则按原有逻辑存入 `storage_ring_items`。
