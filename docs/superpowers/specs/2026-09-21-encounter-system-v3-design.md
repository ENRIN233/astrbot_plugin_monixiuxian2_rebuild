## 1. 对 v2 的修订（定案）

### 1.1 因果失败判定（修订 v2 §10.1 `resolve` 第 6 步）

**v2 缺陷：** 失败时统一执行 `karma - abs(karma_delta)`。对恶行选项（`karma_delta < 0`，如"强行采摘 -5"）失败反而 **+5 因果** —— 玩家可以"故意失败作恶"刷正因果，逻辑自相矛盾。

**v3 规则（成败同向、失败减半；2026-09-22 修订：恶行失败不再全额）：**

| 情形 | 因果变化 | 设计依据 |
|------|----------|----------|
| 成功 | 全额 delta | 事成业成 |
| 失败 | **同向减半**：`sign(delta) × ceil(|delta| / 2)`（−5 → −3，+5 → +3） | 失败已承担"奖励落空 + HP/灵石惩罚"，因果再全额属三重惩罚，会劝退风险选项、架空"风险-回报"三角；减半保留玩家表态（选恶行即恶念），又不至于让人不敢冒险。统一规则免去善恶分叉特判 |
| 中性（delta = 0） | 0 | — |

```python
# v3 resolve() 第 6 步替换（替换 v2 的 karma - abs(karma_delta) 写法）
delta = choice.get("karma_delta", 0)
if is_success or delta == 0:
    applied = delta
else:  # 失败：同向减半，绝对值向上取整
    applied = (1 if delta > 0 else -1) * ((abs(delta) + 1) // 2)
player.karma = max(-1000, min(1000, player.karma + applied))
```

同步修订 v2 §5.2 结果文案：失败时显示 `☯️ 因果：{applied:+d}`。

## 2. 群体奇遇窗口（v3 核心新增）

### 2.1 定位：从"彩蛋"到"锚点"

| 层 | 系统 | 玩家心智 | 回访驱动 |
|----|------|----------|----------|
| 体验层 | 个人奇遇（v2） | 被动惊喜，"玩着玩着掉宝" | 无锚点，随缘 |
| **留存层** | **群体奇遇窗口（v3 新增）** | **预约式赶集**："21:30 天象异变，全群抢" | **每日固定时段 × 3** |
| 社交层 | 偷菜/护园（灵植园 v2） | 群内互怼互动 | 被偷了要去报仇 |

**为什么挂在奇遇系统下：** 窗口事件的叙事外壳就是"天地异象级奇遇"（对应 v2 事件池中的 epic/legendary 档），复用因果、稀有度、奖励公式与文案体系，零新概念。同时它是**传承卡（105 张花卉卡）的唯一产出渠道** —— 传承系统获得途径未实装期间的"期货"，卡片先入储物戒，传承实装后直接消费。

### 2.2 时段与调度

**默认窗口表**（`encounter_config.json` 新增 `group_windows` 节点，可调）：

| 窗口 | 时间 | 类型 | 稀有度档 |
|------|------|------|----------|
| 午间异象 | 每日 11:30 | 抢占型 | rare |
| 黄昏异象 | 每日 17:00 | 协力型 | epic |
| 夜间异象 | 每日 21:30 | 抢占/协力轮换 | epic |
| **周日大异象** | 周日 21:30 | 协力型 | **legendary（唯一传承卡稳定来源）** |

- 每窗口开放时长：**10 分钟**（抢占型名额抢完即提前结算）。
- 调度实现：新增后台任务 `_schedule_group_encounters`（复用 main.py 八大后台任务模板：`while True + try/except + 指数退避`），计算距下一窗口的 sleep 时长 → 到点开窗 → 广播 → 等待 → 结算。
- 广播调用现成的 `_broadcast_to_whitelist_groups(message)`（main.py:626）。

### 2.3 抢占型窗口（天材地宝）

```
[11:30 广播到全部白名单群]
🌀 天地异象！🌀
━━━━━━━━━━━━━━━
灵气在群中汇聚成【上古灵乳】（传说级天材地宝）！
前 3 位发送 /探秘 的修士可入内争夺！
⏰ 10 分钟后入口关闭
```

- 每群前 `rush_slots_per_group`（默认 3）名 `/探秘` 者锁定名额，立即私信式回复进入结果。
- 各自掷 risk（默认 15%，远低于个人奇遇高风险档）：
  - 成功 → 按稀有度奖励公式发放（§2.5）；
  - 失败 → 小惩罚（HP −10%，无因果变动，"宝物灵光护体，将你震退"）。
- 名额满或窗口超时 → 入口关闭广播（简短一行）。

### 2.4 协力型窗口（天魔降世 / 灵潮汇聚）

```
[17:00 广播]
⚔️ 天魔降世！⚔️
━━━━━━━━━━━━━━━
一尊域外天魔投影笼罩诸天，所有修士可出鞘一次！
发送 /讨伐 斩出你的全力一击！
⏰ 10 分钟后天空重归平静
```

- 窗口期内每人限 `/讨伐` 1 次，伤害 roll：`dmg = atk × random(0.8, 1.3)`（不入战斗引擎，纯 roll，避免卡顿）。
- **成功判定（窗口结束时）：**

```
有效参与 = dmg > 0 的参与者（0 伤者不计分母，防挂机恶心人）
ratio = Σdmg / (有效人数 × 均次期望 dmg × 1.05)
ratio ≥ 0.85  → 大胜：全员按贡献分两档发放满额奖励 + 掉落
0.50~0.85     → 惨胜：全员参与奖（满额 × 0.4），掉落减半概率
< 0.50        → 失败：安慰奖（灵石小额），无掉落
```

- 贡献分档：有效参与者按 dmg 排序，前 1/3 得 `×1.3` 档，其余 `×1.0` 档（人头均在广播中点名前三："斩魔首功：XXX"）。

### 2.5 奖励设计与传承卡掉落

**灵石/修为：** 沿用 v2 §12 公式 `base_gold × level_bonus × rarity_mult × risk_mult`，窗口整体再乘 `reward_mult = 2.5`。周 21 窗 × 2.5 倍 → 窗口奇遇占日均收入 **2~4%**，不冲击经济（验证见 §4）。

**传承卡掉落（v3 关键设计）：**

| 窗口稀有度 | 掉落 | 说明 |
|-----------|------|------|
| legendary（周日） | **100% 掉 1 张** | 每群每周保底 1 张 |
| epic | 15% 掉 1 张 | 每群每周期望 ~0.9 张 |
| rare（抢占型） | 不掉卡 | — |

- 卡池 = `impart_cards.json` 105 张花卉卡，按 type 均匀加权（atk/hp/mp 各约 19-20 张权重 20，稀有 type 如 crit_rate 权重 5）。
- 卡片以**物品形式存入储物戒**（"白玫瑰"），**本周重复 type 权重衰减 50%**（软保底池，避免一周开出 5 张同类型）。
- **通胀控制三原则**（传承实装时定案，此处预留）：
  1. 加成建议**同 type 取最大值**（词条化，非叠加以防 105 张全吃变数值爆炸）；
  2. 卡片使用侧限流（如每日赠花 3 次）；
  3. 每群每周产出上限 ~2 张（本设计已满足：1.0 + 0.9 ≈ 1.9）。

**护园灵兽蛋：** legendary 窗大胜时额外 30% 掉"护园灵兽蛋"（联动灵植园 v2 §6，蛋为物品，孵化命令在灵植园侧）。

### 2.6 防刷规则

| 风险 | 对策 |
|------|------|
| 一人多群重复参与 | 全局参与登记 `(window_id, user_id)`，跨群只结算 1 次 |
| 抢占型脚本抢名额 | 名额按**群**分配（每群独立 3 席），单人无跨群收益；`/探秘` 需已完成注册的玩家 |
| 协力型 0 伤混奖 | dmg=0 不计入分母也不发奖；dmg ≥ 100 才算有效参与 |
| 窗口刷屏 | 全流程仅 3 条群消息（开窗广播 / 结算广播 / 可选关闭提示），个人结果均私聊式单发 |

### 2.7 GroupEncounterManager 状态机

```python
class GroupEncounterManager:
    """群体奇遇窗口管理器（纯内存态，重启即重置）"""
    # 状态机: idle → open → settled
    self._current: Optional[dict] = None
    # open 时结构:
    # {
    #   "window_id": "2026-09-21_2130",
    #   "type": "coop" | "rush",
    #   "rarity": "epic",
    #   "event": {...事件定义，从窗口事件池抽选...},
    #   "opened_at": ts, "expires_at": ts,
    #   "participants": {(group_id, user_id): {"dmg": int | "claimed": bool}},
    # }
```

- 窗口事件池：`encounter_config.json` 增 `group_events` 节点（抢占型 8 个、协力型 6 个，文案风格对齐 v2 事件池；初版 14 个即可运转）。
- 重启恢复：不做持久化，重启后 `_current = None`，错过窗口直接等下一班（180s 级 pending 同理，v2 §15-7 已定案可接受）。
- 结算：`_settle()` 在 `expires_at` 触发（后台任务 sleep 至该时刻），发奖励 → 广播结算 → `settled`。

## 4. 数值安全验证

### 4.1 灵石收入占比

以化神期（日均 ~220 万灵石）为例：

| 来源 | 周 21 窗 × 参与 5 窗 | 单窗期望（epic × 2.5） | 周合计 | 占日均 |
|------|---------------------|----------------------|--------|--------|
| 窗口灵石 | 5 | ~83,000 | ~41.5 万 | **~2.7%** | ✅ |

大乘期约 3.5%，仍在 v2 §12.0.5 "1-3%" 原则的容忍上沿，安全。

### 4.2 传承卡产出速率

| 情形 | 每群每周期望 |
|------|-------------|
| 周日 legendary 窗 | 1.0 张 |
| 6 窗 epic × 15% | 0.9 张 |
| **合计** | **~1.9 张/群/周** |

105 张池 × 1.9 张/周 → 单群约 1 年轮完一遍池子；配合"同 type 取最大值"规则，单卡价值 5~10% 单项加成，月增幅可控在 ~2% 综合战力，通胀安全。
